# S3-Queue

A distributed message queue built entirely on S3-compatible object storage. Concurrent producers, background compaction, consumer cursors, and administrative fencing — zero external dependencies beyond S3.

**Based on:** [Leaderless Log Protocol](../../1-leaderless-log-protocol.md) (Layer 1)

## Build Your Own

Tell your favorite coding agent to implement S3-Queue in the language of your choice:

> Implement S3-Queue according to the following spec:
> https://github.com/lakestream-io/leaderless-log-protocol/blob/main/examples/s3-queue/SPEC.md

The [SPEC.md](SPEC.md) is self-contained — it includes the domain model, state machines, S3 key schema, coordination primitives, operation pseudocode, error handling, and a test matrix. Everything a coding agent needs to produce a correct implementation without back-and-forth.

## Use the Reference Implementation

The [`impl/`](impl/) directory contains a Rust implementation generated by a coding agent from the SPEC.

### Quick Start

Start MinIO (local S3):

```bash
cd impl
docker compose up -d
```

Build and run:

```bash
cargo build --release

# Initialize a topic
cargo run -- init my-topic

# Produce messages
cargo run -- produce my-topic "hello world"
cargo run -- produce my-topic "second message"

# Consume and acknowledge
cargo run -- consume my-topic my-consumer
cargo run -- ack my-topic my-consumer 1

# Other operations
cargo run -- status my-topic
cargo run -- compact my-topic --start 1 --end 3
cargo run -- fence my-topic
cargo run -- unfence my-topic
cargo run -- vacuum my-topic
```

### Configuration

| Flag | Env Var | Default |
|------|---------|---------|
| `--endpoint` | `S3Q_ENDPOINT` | `http://localhost:9000` |
| `--bucket` | `S3Q_BUCKET` | `s3-queue` |
| `--access-key` | `S3Q_ACCESS_KEY` | `minioadmin` |
| `--secret-key` | `S3Q_SECRET_KEY` | `minioadmin` |

### Running Tests

```bash
# Start MinIO first
docker compose up -d

# Run integration tests
cargo test --features integration
```
